# speech-lab 零基础入门教程

这份教程假设你还不懂语音增强、神经网络和项目结构。目标不是一次学会所有数学，而是让你先能回答四个问题：

1. 这个项目在解决什么问题？
2. 模型怎样把带噪语音变干净？
3. 训练、验证、测试分别在干什么？
4. 怎样在自己的电脑上运行并看懂结果？

---

## 第一课：语音增强是什么

你在马路上录下一句话，录音里同时有：

- 你的声音；
- 汽车声；
- 风声；
- 周围人的说话声。

语音增强要做的事情，就是尽量保留你的声音，同时压低其他噪声。

可以把它想成一张照片去雾：

```text
带噪录音 = 人声 + 噪声
增强录音 ≈ 被保留的人声 + 被压低的噪声
```

难点在于：算法不能把噪声删得很干净，却顺便把人声的重要部分也删掉。

所以“更安静”不一定等于“更清楚”。这正是本项目 v2 和 v4 结果不同的地方。

## 第二课：为什么不直接用传统滤波器

传统方法通常先估计噪声长什么样，再从频谱里减掉噪声。

这种方法对白噪声比较有效，因为白噪声比较稳定。但面对餐厅人声、街道声等复杂噪声，噪声和人声会重叠，传统方法就容易误判。

本项目 S0 的谱门控基线已经验证了这一点：

- 白噪声：效果明显；
- 粉噪声：效果有限；
- 类人声噪声：基本无效。

因此后面使用 GRU 神经网络，让模型从成对数据里学习“哪些部分更像人声”。

## 第三课：音频怎样交给神经网络

电脑不能直接理解“这是一句话”。它需要先处理音频。

### 1. 波形

波形是音频随时间变化的数值。可以把它想成一条上下起伏的线。

本项目真实数据统一为：

- 16 kHz 采样率；
- 单声道；
- float32 数值；
- clean 和 noisy 长度一致。

### 2. STFT 与频谱图

模型不直接看整条波形，而是通过 STFT 把音频切成很多小片段，再观察每个片段里有哪些频率。

频谱图可以粗略理解为一张图片：

- 横轴：时间；
- 纵轴：频率；
- 颜色或亮度：该时间、该频率有多强。

### 3. 掩蔽

模型输出一张和频谱图差不多大的“掩蔽表”。表里的数值接近 0 或 1：

- 接近 0：这里多半是噪声，压低；
- 接近 1：这里多半是人声，保留；
- 中间值：只保留一部分。

最后把掩蔽乘到带噪频谱上，再还原成波形。

```text
带噪声频谱 × 模型预测的掩蔽 = 增强后的频谱
```

`tiny_gru` 就是负责预测这张掩蔽表的模型。

## 第四课：训练、验证、测试是什么

用学生备考来理解最方便。

### 训练集：平时做的练习题

模型反复看“带噪录音”和对应的“干净录音”，学习怎样减少误差。

本项目当前正式对照实验只使用 128 条训练样本，所以仍属于小规模实验。

### 验证集：模拟考试

训练过程中用验证集检查模型在没直接训练的音频上表现怎样，并决定保存哪一轮权重。

如果训练损失一直下降，验证损失却开始上升，就可能出现过拟合。早停会在验证表现长期不改善时停止训练。

### 测试集：正式考试

测试集用于最后评价模型，不应该反复用来调参数，否则相当于提前看答案。

本项目把 824 条测试样本及其清单冻结，并用 SHA-256 校验，目的就是尽量保证每次实验用的是同一套考题。

**简单记忆：训练用来学，验证用来选，测试用来最后评价。**

## 第五课：项目文件夹分别在干什么

```text
configs/exp/       实验说明书：用什么数据、什么模型、训练多少轮
speechlab/         真正的核心代码
scripts/           下载、清洗、分析等辅助工具
train/run.py       训练入口
eval/run.py        评测入口
tests/             自动检查代码是否正常
data/              本地音频和数据清单
runs/              训练和评测结果
docs/log/          研究过程记录
```

最核心的几个文件：

| 文件 | 作用 |
|---|---|
| `speechlab/models/base.py` | 规定所有增强模型遵守同一接口 |
| `speechlab/models/tiny_gru.py` | GRU 掩蔽模型 |
| `speechlab/dsp/stft.py` | 波形与频谱之间转换 |
| `speechlab/engine/trainer.py` | 训练、验证、早停、保存权重 |
| `speechlab/eval/runner.py` | 逐条增强并汇总指标 |
| `speechlab/data/voicebank.py` | VoiceBank 数据清洗、冻结与加载 |

## 第六课：在 Windows 上运行项目

### 第一步：安装基础软件

建议准备：

- Python 3.11 或 3.12；
- Git；
- 一个文本编辑器，例如 VS Code。

如果 Python 3.14 安装 PyTorch 遇到问题，直接使用 Python 3.12，不必继续硬试。

检查安装：

```bash
python --version
git --version
```

### 第二步：下载项目

```bash
git clone https://github.com/xuy8951-ops/speech-lab.git
cd speech-lab
```

后面的命令都默认你位于项目根目录。

### 第三步：建立虚拟环境

虚拟环境相当于给这个项目单独准备一个工具箱，避免影响电脑上的其他 Python 项目。

PowerShell：

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
```

如果 PowerShell 不允许激活，可以改用 CMD：

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate.bat
```

然后安装依赖：

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 第四步：先跑传统基线

```bash
python eval/run.py configs/exp/000_baseline.yaml
```

这个实验使用合成数据，不需要先下载 VoiceBank。

成功后重点看：

```text
runs/000_baseline/scores.jsonl
runs/000_baseline/summary.csv
```

### 第五步：运行单元测试

```bash
python -m pytest tests/ -q
```

看到类似下面的内容，说明测试通过：

```text
7 passed
```

新增代码后测试数量可能变化，关键是全部通过，而不是永远必须是 7 项。

### 第六步：运行 GRU 过拟合小实验

```bash
python train/run.py configs/exp/001_gru_overfit.yaml
```

这个实验只有 4 个训练样本，目的不是做出好模型，而是检查训练链路是否能正常学习。此前在本机 CPU 上约需 10 分钟，实际时间取决于电脑性能。

建议先完成以上步骤，再接触 VoiceBank 真实数据实验。

## 第七课：怎样读懂 YAML 配置

以 `configs/exp/003_gru_voicebank_multispk.yaml` 为例，可以把它当成实验说明书。

```yaml
seed: 2026
```

固定随机种子，让抽样和训练尽量可复现。

```yaml
data:
  name: voicebank_demand
  max_train: 128
  max_val: 64
```

指定数据集，以及从清单中抽取多少训练和验证样本。

```yaml
model:
  name: tiny_gru
  args:
    hidden: 128
    layers: 2
```

指定使用 GRU 模型及其结构参数。

```yaml
train:
  epochs: 12
  batch: 8
  lr: 0.001
```

- `epochs`：最多训练多少轮；
- `batch`：每次送入多少条样本；
- `lr`：学习率，决定每次参数调整的大致步伐。

```yaml
  early_stop:
    patience: 3
```

验证表现连续多轮没有足够改善时停止，避免无意义地继续训练。

```yaml
output: runs/003_gru_voicebank_multispk
```

指定实验输出目录。

**学习配置时，先改一个参数并记录结果，不要一次改很多个。否则最后无法知道是哪项变化起作用。**

## 第八课：训练和评测命令怎么配合

以 v2 为例：

```bash
python train/run.py configs/exp/003_gru_voicebank_multispk.yaml
python eval/run.py configs/exp/003_gru_voicebank_multispk.yaml
```

第一条命令训练并保存最佳权重。第二条命令读取同一配置里的 `checkpoint`，在冻结测试集上评测。

只评测验证集：

```bash
python eval/run.py configs/exp/003_gru_voicebank_multispk.yaml --split val
```

验证结果会放进 `validation/` 子目录，避免覆盖正式测试结果。

注意：GitHub 不保存模型权重和音频。刚克隆的仓库需要先准备数据并训练，不能直接复现本机已有的 `best.pt`。

## 第九课：怎样看评测结果

打开 `summary.csv`，先找最后一行：

```text
all,all,all,...
```

这一行代表全体测试样本的总体结果。

主要关注：

| 列名 | 含义 |
|---|---|
| `n` | 样本数 |
| `noisy_snr` | 增强前 SNR |
| `enhanced_snr` | 增强后 SNR |
| `delta_snr` | SNR 变化，越高通常越好 |
| `delta_si_sdr` | SI-SDR 变化，越高通常越好 |
| `delta_stoi` | STOI 变化，正数才表示可懂度提高 |

`scores.jsonl` 则是逐样本明细。想查某类噪声或某条音频为什么表现差，需要回到这里。

不要只看总体平均数，还应观察：

- 不同噪声类型；
- 不同输入 SNR；
- 是否有某些条件明显退化。

## 第十课：v1—v5 到底在学什么

可以把五个版本理解成连续的小实验：

- **v1**：先证明真实数据训练、验证、评测整条链路能跑通。
- **v2**：增加一个训练说话人，SNR 大幅提升，说明说话人多样性有帮助。
- **v3**：尝试对数幅度损失，结果更差，记录为负结果。
- **v4**：直接学习 IRM，STOI 损失明显缩小，但 SNR 不如 v2。
- **v5**：组合幅度与 IRM 损失，没有同时得到两者优势。

目前最值得记住的一句话是：

**v2 更擅长提高 SNR，v4 更擅长保持可懂度，但两者都还没有让平均 STOI 变成正提升。**

## 第十一课：常见报错怎么处理

### `python` 不是内部或外部命令

Python 没装好，或没有加入 PATH。重新检查 Python 安装。

### 安装 PyTorch 失败

优先改用 Python 3.11 或 3.12 创建虚拟环境，不要继续在 3.14 上反复尝试。

### 找不到配置文件或模块

先确认命令行当前位于项目根目录，并且路径拼写正确。

### 找不到音频或 `best.pt`

音频和权重没有上传 GitHub。需要先准备数据并训练，或者从本机已有实验目录复制对应文件。

### PESQ 是 NaN

当前 Windows 环境缺少 MSVC 构建工具，PESQ 按可选指标处理，不会阻止 SNR、SI-SDR、STOI 评测。

### 结果和上次不一样

检查是否更换了：

- 配置；
- 数据清单；
- 随机种子；
- 权重文件；
- 训练或测试划分。

## 第十二课：适合初学者的练习顺序

### 练习 1：跑通基线

运行 S0，打开 `summary.csv`，找出白噪声和类人声噪声的差异。

### 练习 2：跑通训练

运行 S1 过拟合实验，观察训练损失是否下降。

### 练习 3：读配置

打开 v2 配置，找出训练样本数、模型名称、学习率、早停参数和输出目录。

### 练习 4：读正式结果

比较 v2 与 v4 的总体行，用自己的话解释“为什么 SNR 更高的版本不一定更好”。

### 练习 5：做一个受控小改动

复制一份配置，只改一个小参数，并把输出目录改成新名字。不要覆盖旧实验，也不要先改模型代码。

## 最后需要掌握的十个词

| 名词 | 简单解释 |
|---|---|
| 语音增强 | 压低噪声，尽量保留人声 |
| 波形 | 音频随时间变化的数值 |
| 频谱 | 不同时间、不同频率的能量分布 |
| STFT | 把波形转成时频表示的方法 |
| 掩蔽 | 决定每个时频点保留多少的表格 |
| GRU | 能利用前后时间信息的神经网络单元 |
| 损失 | 模型输出与目标之间的差距 |
| 过拟合 | 练习题做得很好，新题却做不好 |
| 早停 | 验证表现不再改善时提前停止训练 |
| 冻结测试集 | 不允许随实验随意改变的正式考题 |

学完这份教程后，你已经可以理解项目的基本结构、运行方式和实验结论。下一步才是读具体源码或修改参数，不必一开始就钻研所有数学细节。
