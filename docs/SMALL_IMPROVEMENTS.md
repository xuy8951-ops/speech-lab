# speech-lab 轻量优化建议

这份清单只包含小改进：不换大模型、不重写架构、不做复杂部署，也不要求马上进行全量训练。

建议优先做前三项，因为它们能最快让项目“看得见、听得到、好理解”。

## 1. 保存少量增强后的试听音频

**现在的不便**：评测主要保存指标，无法直接听出 v2 和 v4 的差别。

**小改动**：每次评测额外保存 6—10 条代表性音频，每条包含：

```text
原带噪音频 / v2 增强 / v4 增强 / 对应干净音频
```

可以优先选择低 SNR、高 SNR、餐厅噪声和街道噪声样本。

**价值**：不用先懂指标，也能判断模型有没有把人声弄闷、弄出金属音或残留噪声。

**注意**：试听文件仍放在本地 `runs/`，不必上传 GitHub。

## 2. 自动画训练损失曲线

**现在的不便**：训练日志需要逐行阅读，不直观。

**小改动**：训练结束后自动输出一张 `loss_curve.png`，画出：

- 训练损失；
- 验证损失；
- 最佳 epoch；
- 早停位置。

**价值**：一眼看出模型是否过拟合、最佳权重出现在哪里，以及早停是否合理。

## 3. 自动生成一页实验摘要

**现在的不便**：每次都要打开 CSV，再手动整理结果。

**小改动**：评测结束后额外生成 `report.md`，只放：

- 实验名称；
- 数据规模；
- 最佳 epoch；
- 总体 SNR、SI-SDR、STOI；
- 与上一版本的差值；
- 配置文件路径。

**价值**：每个实验目录都能自己说明自己，减少翻日志和抄数字的工作。

## 4. 增加单条音频推理命令

**现在的不便**：项目主要通过完整实验配置运行，不方便增强一段自己的录音。

**小改动**：增加一个简单入口，例如：

```bash
python enhance.py input.wav --checkpoint runs/005_gru_voicebank_irm/best.pt --output enhanced.wav
```

内部继续复用现有模型、STFT 和统一接口，不需要新架构。

**价值**：以后拿到一段录音就能直接试，不必先制作 manifest 和跑完整测试集。

## 5. 在训练结束时多打印三行信息

**小改动**：训练结束时明确打印：

```text
最佳 epoch：9
最佳验证损失：0.23614
最佳权重：runs/005_gru_voicebank_irm/best.pt
```

**价值**：减少去日志里寻找关键信息的步骤，也能避免误用最后一轮权重。

## 6. 给新验证集冻结脚本补一个小测试

**现在的情况**：三说话人验证集脚本已经加入，但它是在最近一次 `7 passed` 之后新增的。

**小改动**：增加一个小型临时数据测试，检查：

- 每位说话人抽取数量正确；
- 原 p226 样本保持不变；
- 训练与验证没有重复 ID；
- 第二次运行不会改写冻结文件。

**价值**：防止以后修改脚本时无意中改变验证集。

## 7. 给 README 加文档导航

**小改动**：在 README 开头放三个链接：

```text
项目说明书 / 零基础教程 / 轻量优化建议
```

再加一小节“我只想先跑通”，只保留安装、S0 基线和单元测试三条命令。

**价值**：新打开仓库的人不会一开始就被 v1—v5 的所有命令淹没。

## 8. 固定依赖版本范围

**现在的不便**：`requirements.txt` 只有依赖名称，未来新版本可能带来行为差异。

**小改动**：记录当前已验证环境的版本，生成一个单独的 `requirements-lock.txt`，保留原 `requirements.txt` 作为宽松安装入口。

**价值**：以后换电脑或重装环境时，更容易复现当前结果。

**注意**：不需要手动编造版本号，应从当前已能运行的环境导出并核验。

## 9. 给实验配置加统一的简短头部

**小改动**：每份实验配置顶部统一写四行注释：

```yaml
# 目的：本实验只验证什么
# 相比上一版：只改了什么
# 数据：训练、验证、测试各是什么
# 结论：完成后补充一句话
```

**价值**：v1—v5 再多几个版本时，也不容易混淆实验变量。

## 10. 清理本地临时分析文件

**小改动**：把一次性检查脚本、临时压缩包和候选清单分类整理；确认哪些需要保留、哪些可以删除或加入 `.gitignore`。

**价值**：减少误上传和误用旧文件的风险，让项目目录更干净。

**注意**：冻结清单和原始实验结果不要为了“整洁”而删除。

## 推荐实施顺序

```text
1. 保存试听音频
2. 自动画训练曲线
3. 自动生成实验摘要
4. 补验证集冻结测试
5. 增加单条音频推理
6. 其余整理项按需要慢慢做
```

这些改动的共同目标是：不急着让模型更复杂，先让现有成果更容易验证、展示和使用。
